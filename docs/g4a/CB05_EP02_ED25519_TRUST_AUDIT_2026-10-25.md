**Source inspected via GitHub at exact SUT SHA** `9d8bf1c462589ac497e3e03ece48d1d9ab0b9db3`. This is a static, selective code review; **no tests executed by this reviewer**. 190 EP-02 passes are same-session/same-host *reported* results, raw artifacts not received.

## Direct source observations
- `tenir_governance/experimental/ep02_signed_trust.py`: module docstring requires a caller-securely provisioned Ed25519 root public key and expressly says it is neither a consensus trust registry nor atomic execution authorization. `verify_trust_snapshot` receives `root_keys: Mapping[str, Ed25519PublicKey]`, resolves `signed.signer_id` against that map and verifies `signed.signature` over canonical trust bytes. Its docstring states that signature verification alone cannot prevent rollback to an older valid snapshot.
- `tenir_governance/experimental/ep02_binding.py`: `bind` rejects revoked issuers and absent mandate; `revalidate` compares revision/digest and is explicitly **not** authorization to commit.
- `tenir_governance/experimental/ep02_rotation.py`: `validate_transition` requires caller-supplied authenticated snapshots and a prior checkpoint; checks fingerprint and revision, returns `REVISION_ROLLBACK` on decreasing revision. Independence/durability of the prior checkpoint is not established by this pure function.
- `tests/test_ep02_bound_issuer_keys.py`: generates root and issuer Ed25519 private keys in tests; verifies bound issuer key substitution fails, root-signed same-revision key change invalidates old receipt, unbound issuer keys are rejected, and revoked issuer fails despite valid signatures.
- `tests/test_ep02_rollback_witness.py`: creates two `DurableAnchorCAS` stores (local and witness) on local paths with the **same generated root key**; compares them with `assess_anchor`. This tests comparison mechanics, not independent host, credential or custody domains.

## Security interpretation / open questions
1. **Root provisioning is outside the reviewed modules**: inspect application entry points and all callers before concluding no operational key loading exists elsewhere. Define who pins and updates root keys and how compromised roots are revoked.
2. **Signed snapshot freshness**: signature authenticates content, not latest state. Require independently persisted and authenticated monotonic witness head, epoch and quarantine transition binding at admission.
3. **Same-revision equivocation**: a newly root-signed issuer key at the same revision invalidates the prior receipt in a test; define production policy for conflicting valid snapshots, no silent acceptance.
4. **Rotation**: `ep02_rotation` relies on prior checkpoint; test recovery when both local checkpoint and local store are rolled back together.
5. **Trust-domain separation**: test witness with separate host, root/key custody, persistence and independently authenticated verifier. Do not mistake same-process `rollback_witness` for G2.
6. **Unreviewed**: full `ep02_external_cas`, `ep02_durable_cas`, `ep02_commit_authorization`, all trust-input-hardening tests, root rotation, transport authentication, cross-process race and key lifecycle. Audit those before implementation reuse approval.
